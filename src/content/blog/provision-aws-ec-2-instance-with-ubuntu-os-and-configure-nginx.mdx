Hi everyone,

In this article, we will walk you through the steps of provisioning an Amazon Web Services ([AWS](https://aws.amazon.com/)) Elastic Compute Cloud (EC2) instance with [Ubuntu](https://ubuntu.com/) as the operating system and configuring [Nginx](https://www.nginx.com/) on it. To get started, you will need an AWS account. AWS offers a [free tier](https://aws.amazon.com/free/) for newly created accounts, so you can try out the cloud services without any cost.

### Intro to Nginx

> [Nginx](https://www.nginx.com/) is open source software for web serving, reverse proxying, caching, load balancing, media streaming, and more. It started out as a web server designed for maximum performance and stability.

It was designed for maximum performance and stability, making it one of the most popular and widely used software of its kind. If you're in the IT field, there's a high chance you'll encounter Nginx at some point in your career.

### Let's get started

To begin, log in to your AWS account and click on "EC2".

![AWS dashboard](/assets/awsec2/aws_dashboard.png)

Then, click the "Launch Instance" button to open the instance launch wizard.

![launch instance](/assets/awsec2/launch_instance.png)

### Select server OS

Then, on the launch instance page, give your server a name and an OS image. Here I am naming it `codehirise server` and choosing `Ubuntu 22.04`.

![server name and OS image](/assets/awsec2/aws_server_name_45f161b7d5.png)

Next, you'll need to select an instance type. For this tutorial, we'll choose t2.micro as it falls under the free tier, but you can choose any type you prefer. Keep in mind that the cost will vary based on the instance type you choose. To learn more about AWS instance types, see the [AWS instance types](https://aws.amazon.com/ec2/instance-types/) docs.

![instance](/assets/awsec2/instancetype_233a042a78.png)

### Select an SSH key pair

In order to connect to the instance we are about to create, we need an SSH key pair.

We can create a new key pair or select a previously created key pair.

I will create a new key pair with default values for this tutorial.

![ssh key](/assets/awsec2/keypairselect_8af5dd8810.png)

Provide a name for your key and click "Create key pair"; the private key will be downloaded automatically.

![key](/assets/awsec2/sshkeydownload_74c202a9d8.png)

### Configure networking

In the network settings, we need to enable `Allow HTTP traffic from the internet` which will be used to connect to NGINX after it has been deployed.

We also need to allow SSH traffic from anywhere, which is needed to connect to the instance via SSH.

By default, a provisioned instance has a public IP address which we use to connect to the server. Also, when an AWS account is created, AWS creates a default VPC (Virtual Private Cloud) to simplify the experience for new users, and that VPC is used here. This instance will be provisioned in the AWS us-east-1 region.

![network](/assets/awsec2/network_settings.png)

### Configure storage

Finally, for storage, I will leave it as the default setting which is suitable for this tutorial, then click the launch instance button to provision your AWS EC2 instance.

![storage](/assets/awsec2/storage.png)

If everything goes well, you'll see this screen with launch success.

After that, click on the instance ID to view your newly created instance.

![provision ec2 success screen](/assets/awsec2/provision_ec2_76c044c031.png)

You will see your newly created instance in a `running` status. Note that it takes some time to go from the `pending` to the `running` state.

![instance running state](/assets/awsec2/running_fda9b28256.png)

### Connecting to the instance

Once we have successfully provisioned the server, we can connect to it using SSH.

Navigate to the directory where you have the SSH private key which we downloaded earlier.

Before we can actually SSH into the server, we need to restrict the permissions on our SSH key.

To do that, run:

```bash
chmod 400 <your key >
```

![change key permission](/assets/awsec2/chmod_764b5f2526.png)

Then run the following to connect to the instance using SSH.

```bash
ssh -i "your key name .pem" ubuntu@instance_public_ip
```

Here we specify `ubuntu` as the username since that is the default username for Ubuntu which we selected in earlier steps.

We can also use the instance's `Public DNS` name for SSH instead of its public IP.

After connecting to the instance for the first time you will get a prompt to continue. Type `yes` to continue.

![ssh to server](/assets/awsec2/ssh_in_server_080d6f57a9.png)

Voila, you are now on the server.

### Install Nginx on an Ubuntu server

Installing Nginx is pretty straightforward.

First, we need to update the `apt` repositories since this is a fresh Ubuntu server. There might be new updates in the repositories.

Here `apt` is Ubuntu's default package manager.

Run:

```bash
sudo apt update
```

![apt update](/assets/awsec2/aptupdate_fe3154adbb.png)

After that, run the following and press `y` at the confirmation prompt:

```bash
sudo apt install nginx
```

![install nginx](/assets/awsec2/aptanginx_d1c7e70f0b.png)

After installation, run:

```bash
sudo systemctl status nginx
```

![systemctl status](/assets/awsec2/systemctlnginx_6d53f3296d.png)

Now we will visit the public IP address of our instance to see Nginx in action.

![Nginx in browser](/assets/awsec2/nginxweb_5d0ff7c289.png)

Nginx binds to port 80 on the server by default, and since we opened that port when provisioning the instance, we can see the Nginx welcome page by visiting the public IP in a web browser.

<Alert type="info">
Some systems need additional OS-level configuration, like firewall rules, to open ports, but in this Ubuntu image it is not necessary: port 80 is open by default at the OS level.
</Alert>

As the final step, we need to remove the created resources to avoid getting billed.

Terminating the instance also removes the EBS root volume by default, which would otherwise keep incurring cost.

![Terminate instance](/assets/awsec2/terminate_93c5fb3a7c.png)

**Thank you for reading.**
